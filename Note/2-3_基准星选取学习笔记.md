## 1. 本章在 RTK 流程中的位置

上一章已经把同步后的基站、流动站原始观测构造成站间单差。本章需要在每个卫星系统中选取一颗质量最好的卫星作为参考星，为下一步形成站星双差做准备。

```text
基站、流动站同步观测历元
            ↓
      构造站间单差
            ↓
  单差周跳探测与质量控制
            ↓
 GPS、BDS分别筛选参考星候选
            ↓
  每个系统选择一颗参考星
            ↓
  其它卫星单差减参考星单差
            ↓
      形成站星双差观测
            ↓
 RTK浮点解、模糊度固定与Ratio检验
```

参考星选取不是独立于单差质量控制的步骤。只有通过前一阶段质量检查的单差卫星，才有资格成为参考星。

## 2. 为什么需要参考星

站间单差能够消除同一卫星对应的卫星钟差和卫星端硬件延迟，但仍然保留：

- 基站和流动站之间的接收机钟差；
- 接收机端硬件延迟差；
- 站间单差模糊度；
- 残余电离层、对流层及噪声。

为了继续消除接收机端公共误差，需要在同一卫星系统中选一颗参考星，再让其它卫星的站间单差与参考星的站间单差求差。这一步称为星间求差；它与之前的站间求差组合后，就是站星双差。

参考星会参与该系统内几乎所有双差观测方程。如果参考星自身发生周跳、信号弱或星历异常，它的误差将传播到同系统所有双差，因此参考星必须是质量最可靠的候选卫星之一。

---

## 3. 基本符号与双差方向

本笔记沿用上一章的站间单差方向：

$$
\Delta_{BR}(\cdot)=(\cdot)_R-(\cdot)_B
$$

设：

| 符号 | 含义 |
|---|---|
| $B$ | 基站 |
| $R$ | 流动站 |
| $i$ | 普通卫星，即参与双差的非参考星 |
| $j$ | 参考星 |
| $G$ | 某一卫星系统，例如 GPS 或 BDS |
| $f$ | 频率 |
| $P_{BR,f}^{i,G}$ | 卫星 $i$ 的伪距站间单差 |
| $L_{BR,f}^{i,G}$ | 卫星 $i$ 的载波站间单差 |
| $\nabla_{ij}$ | 星间求差算子，本笔记采用“普通星 $i$ 减参考星 $j$” |

定义星间求差：

$$
\nabla_{ij}(\cdot)=(\cdot)^i-(\cdot)^j
$$

因此站星双差算子为：

$$
\nabla_{ij}\Delta_{BR}(\cdot)
$$

整个工程必须固定这个方向。若下一章使用相反的星间方向，则设计矩阵、观测向量和模糊度符号都要同步反向；不能只修改某一个公式。

## 4. 从站间单差到站星双差

### 4.1 两颗卫星的站间单差

对同一系统 $G$ 的普通卫星 $i$ 和参考星 $j$，都有各自的站间单差观测：

$$
P_{BR,f}^{i,G},\quad L_{BR,f}^{i,G}
$$

$$
P_{BR,f}^{j,G},\quad L_{BR,f}^{j,G}
$$

它们都含有相同系统、同一频率的站间接收机钟差和接收机端硬件延迟差。

### 4.2 伪距双差

普通星的单差减参考星的单差：

$$
P_{BR,f}^{ij,G}
=P_{BR,f}^{i,G}-P_{BR,f}^{j,G}
$$

展开几何距离项：

$$
\rho_{BR}^{ij,G}
=\left(\rho_R^{i,G}-\rho_B^{i,G}\right)
-\left(\rho_R^{j,G}-\rho_B^{j,G}\right)
$$

也可写成：

$$
\rho_{BR}^{ij,G}
=\rho_R^{i,G}-\rho_B^{i,G}
-\rho_R^{j,G}+\rho_B^{j,G}
$$

在短基线条件下，电离层和对流层双差残差较小，简化模型可写为：

$$
P_{BR,f}^{ij,G}
\approx \rho_{BR}^{ij,G}+\varepsilon_{P,BR,f}^{ij,G}
$$

### 4.3 载波相位双差

$$
L_{BR,f}^{ij,G}
=L_{BR,f}^{i,G}-L_{BR,f}^{j,G}
$$

完整模型中包括几何距离、电离层、对流层、双差模糊度和噪声。短基线简化后：

$$
L_{BR,f}^{ij,G}
\approx \rho_{BR}^{ij,G}
+\lambda_f^G N_{BR,f}^{ij,G}
+\varepsilon_{L,BR,f}^{ij,G}
$$

双差模糊度定义为：

$$
N_{BR,f}^{ij,G}
=\left(N_{R,f}^{i,G}-N_{B,f}^{i,G}\right)
-\left(N_{R,f}^{j,G}-N_{B,f}^{j,G}\right)
$$

也就是：

$$
N_{BR,f}^{ij,G}
=N_{R,f}^{i,G}-N_{B,f}^{i,G}
-N_{R,f}^{j,G}+N_{B,f}^{j,G}
$$

在正确处理整周和相位硬件初始项的模型下，双差模糊度具有整数特性，这是后续 LAMBDA 固定的基础。

## 5. 双差消除或削弱的误差

| 误差项 | 站间单差后 | 站星双差后 |
|---|---|---|
| 卫星钟差 | 已消除 | 继续保持消除 |
| 卫星端伪距硬件延迟 | 已消除 | 继续保持消除 |
| 卫星端相位初相与硬件延迟 | 已消除或吸收到模糊度模型 | 继续保持消除 |
| 接收机钟差 | 保留站间差 | 消除 |
| 接收机伪距硬件延迟 | 保留站间差 | 同系统同频下消除 |
| 接收机端相位初相与硬件延迟 | 保留站间差 | 同系统同频下消除 |
| 电离层延迟 | 短基线下削弱 | 进一步形成双差残差，短基线可近似较小 |
| 对流层延迟 | 短基线下削弱 | 进一步形成双差残差，短基线可近似较小 |
| 轨道误差 | 削弱 | 短基线下继续削弱 |
| 观测噪声 | 增大 | 继续组合，相关性与权阵不能忽略 |

“消除”依赖于相同系统、相同频率以及同步观测等条件。GPS 与 BDS 的接收机钟差参数和硬件偏差不能简单当成完全相同，所以不能跨系统选同一颗参考星或直接构造 GPS-BDS 星间差。

## 6. 为什么 GPS 和 BDS 必须分别选择参考星

PDF 明确要求：每个卫星导航系统各选取一颗卫星作为参考星。

当前工程约定：

| 数组下标 | 卫星系统 |
|---:|---|
| `0` | GPS |
| `1` | BDS |

因此：

```cpp
DDObs->RefPrn[0]   // GPS参考星PRN
DDObs->RefPos[0]   // GPS参考星在SdSatObs[]中的位置

DDObs->RefPrn[1]   // BDS参考星PRN
DDObs->RefPos[1]   // BDS参考星在SdSatObs[]中的位置
```

分别选星的主要原因：

1. GPS 和 BDS 使用不同信号频率；
2. 两个系统可能具有不同的接收机系统钟差；
3. 系统间硬件延迟通常不能在简单星间差中消除；
4. 后续双差模糊度和设计矩阵需要按系统组织；
5. 某个系统没有合格参考星时，不应影响另一个系统单独形成双差。

## 7. 参考星候选必须满足的质量要求

PDF 第 5 页列出了五类要求。程序实现时应先做硬性淘汰，再在合格候选中比较高度角或 CN0。

### 7.1 没有粗差和周跳

候选单差卫星必须已经通过：

- 原始伪距、载波完整性检查；
- LockTime 连续性检查；
- Parity known / 半周状态检查；
- 单差 MW、GF 周跳检查；
- 其它粗差检查。

在当前结构中，最直接的入口是：

```cpp
SDObs->SdSatObs[k].Valid
```

`DetRefSat()` 应在 `DetectCycleSlip()` 之后调用，否则 `Valid` 还不能代表最终的单差质量。

当前 `Valid` 的类型是 `short`，默认值为 `-1`，`FormSDEpochObs()` 对可用共同星赋值为 `1`。因此不能写：

```cpp
if (SdSat.Valid)
```

因为 C++ 会把 `-1` 也判断为真。应明确写成：

```cpp
if (SdSat.Valid != 1)
{
    continue;
}
```

### 7.2 没有半周问题

两个测站、两个频率的载波都应具有可靠的奇偶/半周状态。只要参考星某个频率存在半周不确定性，该频率对应的所有双差都会受到影响。

当前 `SATOBSDATA::half[2]` 实际保存 OEM7 tracking status 中的 `Parity known` 位。实现时应按真实语义判断：通常 `1` 表示奇偶状态已知，`0` 表示可能存在半周不确定性，不能因为字段名叫 `half` 就把 `1` 理解成发生半周。

### 7.3 星历正常，卫星位置计算成功

当前工程使用：

```cpp
EpkA->SatPVT[nBas].Valid
EpkB->SatPVT[nRov].Valid
```

只有两站同一卫星的 PVT 都有效，才允许作为参考星。这样可以排除：

- 没有对应广播星历；
- 星历过期；
- 卫星位置或钟差计算失败；
- 不支持的卫星系统。

这里存在一个很危险的默认值陷阱：`SATMIDRES` 构造时将 `Elevation` 初始化为 $\pi/2$，也就是 90°，同时将 `Valid` 初始化为 `false`。如果代码先比较高度角、没有先检查 `Valid`，尚未成功计算 PVT 的卫星反而可能凭借默认 90° 被错误选为参考星。

### 7.4 高度角最大或 CN0 最大

PDF 给出的优选指标是：

- 高度角最大，例如高于约 $40^\circ$；或
- 载噪比 CN0 最大，并满足阈值，例如两个频率均大于 `35 dB-Hz`。

本章第 7 页给出的具体逻辑是：先要求流动站两个频率 CN0 都高于阈值，然后在候选星中选择高度角最大的卫星。

高度角大的卫星通常具有：

- 较短的大气传播路径；
- 较小的多路径风险；
- 较稳定的跟踪状态；
- 更好的观测几何和信号质量。

但“最高高度角”不等于“无条件最好”。它仍然必须先通过所有硬性质量检查。

### 7.5 连续观测时间达到要求

PDF 示例阈值为 `6 s`。当前工程已有：

```cpp
EpkB->SatObs[nRov].LockTime[0]
EpkB->SatObs[nRov].LockTime[1]
```

候选参考星的两个频率都应连续锁定足够长时间。刚刚重新捕获、LockTime 很短的卫星不适合作为参考星，因为其载波弧段尚不稳定，周跳或半周状态风险更高。

## 8. 为什么主要使用流动站质量选择参考星

PDF 的假设是：基准站通常架设在视野开阔、观测条件良好的固定环境中，因此参考星优选主要看流动站质量。

实现上可以使用：

```cpp
const int nRov = SDObs->SdSatObs[k].nRov;

EpkB->SatObs[nRov].cn0[0]
EpkB->SatObs[nRov].cn0[1]
EpkB->SatObs[nRov].LockTime[0]
EpkB->SatObs[nRov].LockTime[1]
EpkB->SatPVT[nRov].Elevation
```

但是“主要看流动站”不代表完全不检查基站。基站仍应满足：

- 原始观测存在；
- 相位没有粗差和周跳；
- 半周状态可靠；
- PVT 计算有效；
- 对应索引合法。

对于教学版短基线程序，推荐使用“流动站指标负责排序，两站状态共同负责准入”的策略。

## 9. 高度角与 CN0 的单位及来源

### 9.1 高度角

当前 `SATMIDRES::Elevation` 的单位是弧度，由 `SatPVTCalculation()` 调用 `CompSatElAz()` 计算。

如果阈值写成度，例如：

```text
40°
```

比较前必须转换：

```cpp
const double minElevation = 40.0 * Deg2Rad;
```

不能直接写：

```cpp
if (Elevation > 40.0)
```

因为 `40.0` 弧度远大于正常高度角范围。

### 9.2 载噪比

当前 `SATOBSDATA::cn0[2]` 来自 OEM7 RANGE 消息，通常以 `dB-Hz` 表示。

本章示例条件是：

```cpp
RovSat.cn0[0] >= 35.0 &&
RovSat.cn0[1] >= 35.0
```

应要求两个实际用于双差的频率都达到门限，而不是只检查频率 0。

### 9.3 当前配置缺口

`RTKConfig.ini` 目前只有通用的 `ElevThreshold=15.0`，没有单独的：

```ini
RefSatElevThreshold=40.0
RefSatCN0Threshold=35.0
RefSatLockTimeThreshold=6.0
```

PDF 中的 `40°`、`35 dB-Hz`、`6 s` 是示例值。初版可以在 `DetRefSat()` 中定义清晰的局部常量；更完整的版本应把它们加入配置结构和配置文件，便于不同数据集调整。

## 10. 当前 `DDCOBS` 结构体的含义

当前工程定义的关键字段为：

```cpp
struct DDCOBS
{
    int RefPrn[2], RefPos[2];
    int Sats, DDSatNum[2];
    double FixedAmb[MAXCHANNUM * 4];
    double ResAmb[2], Ratio;
    float FixRMS[2];
    double dPos[3];
    bool bFixed;
};
```

| 字段 | 本章中的意义 |
|---|---|
| `RefPrn[0]` | GPS参考星卫星号 |
| `RefPrn[1]` | BDS参考星卫星号 |
| `RefPos[0]` | GPS参考星在 `SDObs->SdSatObs[]` 中的下标 |
| `RefPos[1]` | BDS参考星在 `SDObs->SdSatObs[]` 中的下标 |
| `DDSatNum[0]` | GPS非参考双差卫星数量，通常是合格GPS共同星数减1 |
| `DDSatNum[1]` | BDS非参考双差卫星数量，通常是合格BDS共同星数减1 |
| `Sats` | 总双差卫星/模糊度组织相关计数，需与后续矩阵定义保持一致 |

构造函数已正确使用：

```cpp
RefPrn[0] = RefPrn[1] = -1;
RefPos[0] = RefPos[1] = -1;
```

这里的 `-1` 表示该系统尚未找到参考星。PDF 第 7 页自动提取文字显示“置为1”，结合结构体和数组语义，应理解为“置为 -1”。如果初始化为 `1`，程序会错误地把单差数组下标 1 当作已经选中的参考星。

## 11. 双差观测值是否必须存入结构体

PDF 第 6 页提出“是否必须将双差观测值定义为结构体成员变量”。答案是：不一定。

### 方案一：不长期保存双差值

在 `RTKFloat()` 构造矩阵时，根据：

- `SDObs->SdSatObs[]`；
- `DDObs->RefPos[]`；
- 当前普通卫星位置；

即时计算：

```cpp
ddP = sdSat.dP[freq] - refSat.dP[freq];
ddL = sdSat.dL[freq] - refSat.dL[freq];
```

优点：

- 避免重复存储；
- 参考星变化时不会留下旧双差；
- 数据一致性更容易保证。

### 方案二：增加双差观测结构

适合需要大量调试输出、残差分析或跨模块复用双差值的程序。

缺点是必须同步维护卫星索引、参考星变化和有效状态，结构会更复杂。

对当前本科教学工程，优先采用方案一：在浮点解建立方程时即时计算双差，`DDCOBS` 只保存参考星信息、计数和解算结果。

## 12. `DetRefSat()` 函数职责与接口

当前声明为：

```cpp
void DetRefSat(
    const EPOCHOBSDATA* EpkA,
    const EPOCHOBSDATA* EpkB,
    SDEPOCHOBS* SDObs,
    DDCOBS* DDObs);
```

建议固定参数语义：

| 参数 | 含义 |
|---|---|
| `EpkA` | 基站历元 |
| `EpkB` | 流动站历元 |
| `SDObs` | 已形成且完成周跳检测的站间单差历元 |
| `DDObs` | 输出GPS/BDS参考星PRN和在单差数组中的位置 |

函数只负责选参考星，不应在这里完成整个双差最小二乘解算。

更清楚的参数名称可以是：

```cpp
void DetRefSat(
    const EPOCHOBSDATA* BasEpk,
    const EPOCHOBSDATA* RovEpk,
    const SDEPOCHOBS* SDObs,
    DDCOBS* DDObs);
```

其中 `SDObs` 理论上也可以是 `const`，因为选星函数不应修改单差观测。

## 13. `DetRefSat()` 推荐算法

### 13.1 初始化

每个历元重新选择时先写：

```cpp
DDObs->RefPrn[0] = -1;
DDObs->RefPrn[1] = -1;
DDObs->RefPos[0] = -1;
DDObs->RefPos[1] = -1;
DDObs->DDSatNum[0] = 0;
DDObs->DDSatNum[1] = 0;
DDObs->Sats = 0;
```

并分别准备 GPS、BDS 当前最大高度角：

```cpp
double maxElevation[2] = { -1.0, -1.0 };
```

### 13.2 遍历单差共同卫星

对 `k = 0 ... SDObs->SatNum-1`：

1. 判断 `SdSatObs[k].System` 是 GPS 还是 BDS，映射为系统下标 `0/1`；
2. 明确检查 `Valid == 1`，粗差、周跳或默认 `-1` 状态直接跳过；
3. 检查 `nBas`、`nRov` 是否处于合法数组范围；
4. 检查两站 `SatPVT[].Valid`；
5. 检查两站两个频率的 Parity/半周状态；
6. 检查流动站两个频率的 CN0 是否达到阈值；
7. 检查流动站两个频率 LockTime 是否达到阈值；
8. 检查流动站高度角是否达到最低门限；
9. 若高度角大于该系统当前最大值，则更新 `RefPrn` 和 `RefPos`。

### 13.3 伪代码

```cpp
RefPrn[GPS] = RefPrn[BDS] = -1
RefPos[GPS] = RefPos[BDS] = -1
maxElevation[GPS] = maxElevation[BDS] = -1

for 每颗单差卫星 k
{
    sd = SDObs->SdSatObs[k]

    systemIndex = GPS ? 0 : BDS ? 1 : invalid
    if 系统不支持
        continue

    if sd.Valid不是可用状态
        continue

    if nBas或nRov越界
        continue

    basObs = EpkA->SatObs[nBas]
    rovObs = EpkB->SatObs[nRov]
    basPvt = EpkA->SatPVT[nBas]
    rovPvt = EpkB->SatPVT[nRov]

    if 两站PVT任一无效
        continue

    if 两站任一频率存在半周/Parity未知
        continue

    if 流动站任一频率CN0低于阈值
        continue

    if 流动站任一频率LockTime低于阈值
        continue

    if 流动站高度角低于参考星最低门限
        continue

    if 流动站高度角 > maxElevation[systemIndex]
    {
        maxElevation[systemIndex] = 流动站高度角
        RefPrn[systemIndex] = sd.Prn
        RefPos[systemIndex] = k
    }
}
```

## 14. 参考星选取后的计数

选中参考星后，还应统计每个系统实际可用于双差的非参考卫星数。

若某系统有 $m_G$ 颗合格共同卫星并且成功选出参考星，则：

$$
DDSatNum_G=m_G-1
$$

如果：

- 只有 1 颗合格共同卫星，则虽然可以把它记为参考星，但没有其它卫星可与它形成双差，`DDSatNum=0`；
- 没有合格参考星，则 `RefPos=-1`、`RefPrn=-1`、`DDSatNum=0`；
- 某系统少于满足后续未知数要求的双差数量，则该系统不能独立贡献完整定位解。

需要提前规定 `DDObs->Sats` 的准确含义：是所有合格共同星数量、所有非参考双差卫星数量，还是双频模糊度总数。当前注释略有歧义，后续编写 `RTKFloat()` 前必须统一。

## 15. 参考星切换问题

如果每个历元都简单选择最高高度角卫星，高度角接近的两颗卫星可能反复交替成为参考星。这会导致：

- 双差模糊度基准发生变化；
- 状态向量和协方差需要转换；
- 残差时间序列出现不连续；
- EKF 模式尤其难以维持连续状态。

### 教学版最小二乘方案

当前程序计划先实现逐历元最小二乘，因此可以每个历元重新选取最高高度角参考星，逻辑较简单。

### 连续滤波或更稳定方案

应采用参考星保持策略：

1. 上一历元参考星仍然有效且质量合格时，优先继续使用；
2. 只有参考星失效、发生周跳、低于门限或离开视野时才切换；
3. 切换时转换双差模糊度基准或重新初始化相应状态。

本章初版 `DetRefSat()` 可先实现逐历元选星，但笔记和函数注释中应明确这一限制。

## 16. 建议的容错处理

| 异常情况 | 建议处理 |
|---|---|
| 任一输入指针为空 | 直接返回，并保持 `RefPrn/RefPos=-1` |
| `SDObs->SatNum` 越界 | 限制循环到 `MAXCHANNUM` |
| `nBas` 或 `nRov` 越界 | 跳过该卫星 |
| 系统不是 GPS/BDS | 跳过 |
| `Valid` 不可用 | 跳过 |
| 两站PVT任一失败 | 跳过 |
| CN0、LockTime、半周状态不合格 | 跳过 |
| 某系统无参考星 | 保持该系统 `RefPrn/RefPos=-1` |
| 某系统仅一颗候选星 | 可记录参考星，但该系统双差数量为0 |
| 两颗星高度角完全相同 | 可保留先找到的卫星，保证结果确定性 |

不建议用 `memset(DDObs, 0, sizeof(DDCOBS))` 初始化，因为“未找到参考星”的正确哨兵值是 `-1`，而不是 `0`，并且结构体后续还保存其它解算结果。

## 18. 推荐的函数调用顺序

```cpp
// 1.取得同步双站历元
GetSynObs(...);

// 2.分别进行卫星PVT计算和必要的单站质量控制
SatPVTCalculation(... BasEpk ...);
SatPVTCalculation(... RovEpk ...);

// 3.构造站间单差
FormSDEpochObs(
    &Raw.BasEpk,
    &Raw.RovEpk,
    &Raw.SdObs);

// 4.单差周跳探测和最终质量标记
DetectCycleSlip(&Raw.SdObs);

// 5.GPS、BDS分别选择参考星
DetRefSat(
    &Raw.BasEpk,
    &Raw.RovEpk,
    &Raw.SdObs,
    &Raw.DDObs);

// 6.建立双差观测方程并计算浮点解
RTKFloat(...);
```

实际实现中，`DetectCycleSlip()` 如果要检查两站 LockTime/Parity，可能需要额外接收 `BasEpk`、`RovEpk` 或利用 `nBas/nRov` 访问原始状态；当前仅传入 `SDEPOCHOBS*` 的接口可能不够完整。

### 当前工程的接入状态

目前 `DetRefSat()` 虽然已经在 `GPS_Structs.h` 中声明，并在 `RTK.cpp` 中保留了函数位置，但函数体仍为空，而且全工程尚未找到调用点。`DetectCycleSlip()` 和 `RTKFloat()` 也仍是空实现；`RTKNav.cpp` 当前在进入 RTK 模式后会提示流程尚未实现并退出。

因此，后续不能只填完 `DetRefSat()` 就认为参考星选取已经真正运行，还必须按上述顺序把它接入 RTK 历元处理主循环，并确保调用前已经完成两站 PVT、站间单差和单差质量控制。

## 20. 容易出现的错误

| 错误 | 后果 |
|---|---|
| GPS、BDS共用一颗参考星 | 跨系统钟差和硬件偏差无法按简单双差消除 |
| 将 `RefPos` 初始化为 `1` 或 `0` | 未选中时误引用有效数组元素 |
| 把 `RefPos` 当作原始 `SatObs[]` 下标 | 实际它应指向 `SdSatObs[]`，导致访问错星 |
| 只检查PRN、不检查系统 | G12 与 C12 发生错误对应 |
| 在周跳探测前选择参考星 | 可能把发生周跳的卫星传播给全部双差 |
| 只检查流动站PVT，不检查基站PVT | 双差几何项使用无效卫星位置 |
| 只检查一个频率CN0 | 另一频率质量差却仍参与双频解算 |
| 把弧度高度角与度数阈值直接比较 | 所有卫星被错误接受或拒绝 |
| 将 `half==1` 直接理解为发生半周 | 与当前保存的 Parity known 语义相反 |
| 每历元频繁切换参考星而不处理模糊度基准 | 滤波状态和双差模糊度不连续 |
| 选到参考星后把参考星也当普通星构造双差 | 生成恒为0的自身双差方程 |
| 某系统只有一颗星仍尝试解算 | 没有可用星间双差观测 |
| 先按最高高度角选星，再检查质量 | 最高星不合格时可能遗漏后续合格候选 |

## 23. 本章最终结论

参考星选取的本质不是“直接找最高的卫星”，而是：

1. 先按系统把 GPS 和 BDS 候选分开；
2. 先检查单差质量、粗差周跳、半周状态、两站PVT、双频CN0和连续锁定时间；
3. 只在全部合格的候选中，选择该系统高度角最大的卫星；
4. 将其 PRN 和在 `SdSatObs[]` 中的位置分别保存到 `RefPrn[system]`、`RefPos[system]`；
5. 若没有合格卫星，必须用 `-1` 明确表示“未选中”；
6. 后续每颗普通卫星都用自己的站间单差减去同系统参考星的站间单差，形成站星双差。

对当前工程而言，`DDCOBS` 已经具备保存 GPS/BDS 参考星的基本字段，真正需要实现的是空的 `DetRefSat()`，并在实现前明确质量标志、Parity known 语义、CN0/LockTime门限和参考星切换策略。参考星选取验证正确之后，才适合继续编写 `RTKFloat()` 的双差矩阵。
